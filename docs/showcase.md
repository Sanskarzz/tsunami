# CLI showcase reference

The maintained setup/recovery guide is [Getting Started](getting-started.md); the sole presentation script is [the controlled walkthrough](demo-walkthrough.md). This page preserves links from [retained CLI showcase evidence](../examples/showcase/README.md).

In an already prepared, explicitly owned lab, `make showcase-check` is read-only. `make showcase` creates three assessments; `make showcase-extended` creates seven and requires the property fixtures. These are separate automated CLI campaigns, not the browser rehearsal. Both use scripted Mecatl and automatic owned-lab approvals, never human/customer authorization or finding review. Optional local schemas use `python3 scripts/showcase.py run --include-property --toolkit PATH`. These campaigns require explicit capacity planning and must not run implicitly.

Preparation rotates disposable data/access and selects new builds. Consult Getting Started before maintenance; never wipe history or clear Stop gates. See [verification and limits](verification.md) and [the original guide](https://github.com/Sanskarzz/tsunami/blob/44d20cb63cde7d3c5f0fde20113404222f185d5d/docs/showcase.md).
